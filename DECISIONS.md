# Решения и допущения

ТЗ оставляло развилки. Ниже — что решили сами и что сознательно расширили по запросу сверх исходного задания.

## Роли

- Кроме постановщика и исполнителя добавлена роль **администратор** (админка, блокировка, смена ролей). Сид создаёт одного админа.
- Саморегистрация выдаёт только роль **исполнитель**. Постановщика назначает админ.
- Исполнителем задачи может быть только пользователь с ролью executor. Постановщик и админ задачу себе назначить не могут.

## Регистрация vs «открытая регистрация выключена»

- Signup через клиентский ключ Supabase выключен (как в ТЗ).
- По запросу сделана регистрация через серверный API + письмо подтверждения (React Email + SMTP). Это не обход RLS: пользователь всё равно создаётся на сервере, роль всегда executor.

## Задачи

- Исполнитель при создании обязателен.
- Редактировать поля задачи (название, объект, исполнитель, дедлайн) может постановщик/админ в любом статусе. Статус при этом так не меняется.
- Удаление объекта удаляет его задачи и историю (через серверные функции, история напрямую API-клиенту недоступна).
- Возврат на доработку: комментарий минимум 3 символа.

## Уведомления и «онлайн»

- Транспорт — **NestJS WebSocket (Socket.IO)**. Онлайн в админке — presence в памяти API. Уведомления пишет база (триггеры + cron), Nest слушает вставки и пушит в сокет пользователя.
- Дедлайны: раз в минуту Nest вызывает `dispatch_deadline_notifications`. Тот же путь доступен как `GET /api/cron/deadlines` (для внешнего cron).

## Файлы

- Аватары и вложения задач идут в S3 (ключи в env). Загрузка через Nest `/api/upload`, секреты AWS на клиент не попадают. Next проксирует `/api/*` на Nest.
- Только JPG/PNG/WEBP, до 5 МБ. Аватар кропается до квадрата 512×512.

## Что не успели / сознательно не делали

- Нет сброса пароля и двухфакторки.
- Нет отдельного мобильного приложения — есть адаптивная вёрстка.
- Нет полноценных e2e против живой базы Supabase (юнит-тесты покрывают статусы, валидацию и дедлайны; RLS проверяется миграцией и ручным сценарием).
- Нет версионирования файлов в S3 и удаления объекта из бакета при удалении вложения (в базе запись снимается).
- На бесплатном Hobby Vercel минутный cron может быть недоступен — в README запасной вариант через cron-job.org.
